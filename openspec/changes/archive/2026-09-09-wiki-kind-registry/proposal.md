## Why

Wiki kind policies and guidance currently drift between Core, navigation, CLI, and skills. One validated declarative registry should make ordinary additions and wording changes configuration-only.

## What Changes

- Ship a validated shared registry with bilingual guidance and existing status/date/source/heading policies.
- Derive recognition, navigation, CLI explanations and API projections from that registry.
- Add initiative and catalog without status vocabularies or heading scaffolds; preserve all existing semantics including roadmap.
- Add an accessible Chinese Wiki type guide dialog and deterministic generated English skill guidance with drift checks.
- Document explicit rebuild/install/refresh and migration boundaries; perform targeted tests and isolated authenticated UI checks only.

## Capabilities

### New Capabilities
- `wiki-kind-registry`: Canonical configuration, consumer projections, help, generation, and compatibility boundaries.

### Modified Capabilities
- `wiki-store`: Derive canonical recognition and field/heading policies from the shipped registry while preserving existing content behavior.
- `wiki-cli`: Add kind introspection and derive create-time date requirements from registry policy.

## Impact

Core Wiki model and lint, CLI commands, Web navigation/API/help, skill generation and documentation. No production deployment, commit, push, page migration, review mutation, or unrelated changes are authorized.
