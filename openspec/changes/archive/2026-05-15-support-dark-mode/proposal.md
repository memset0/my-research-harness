## Why

The dashboard's CSS already ships a full set of dark-theme tokens — `apps/web/app/globals.css` defines a `.dark` block with every semantic token (`--background`, `--foreground`, `--card`, `--sidebar*`, etc.) and `@custom-variant dark (&:is(.dark *))` is declared — but no runtime ever sets the `dark` class, so the dashboard is light-only in practice. Users running long-tail experiments on the cluster regularly leave the dashboard open overnight; the unmitigated light background is uncomfortable at low ambient light. The tokens are already authored, the missing piece is roughly 100 lines of provider + UI + storage glue.

## What Changes

- Add `next-themes` as the runtime that toggles `.dark` on `<html>` and persists the user's preference across reloads.
- Wrap `<body>` (inside `app/layout.tsx`) in a new `ThemeProvider` client component configured with `attribute="class"`, `defaultTheme="system"`, `enableSystem`, and `disableTransitionOnChange`. Add `suppressHydrationWarning` to `<html>` so React doesn't error on the server-vs-client class mismatch.
- Add a new `ThemeToggle` segmented control to the **sidebar header** (the row that currently contains only the `memon` wordmark `Link` at `apps/web/components/app-sidebar.tsx:117-124`). Logo stays left-aligned; the toggle sits right-aligned in the same row (`flex items-center justify-between`).
- The toggle exposes **three** modes — Light / Dark / System — as a single-select segmented control with an animated indicator (a `bg-background` pill that translates between the three slots on selection change, using `transform` + `transition-transform`).
- Install the shadcn `toggle-group` primitive (`pnpm dlx shadcn@latest add toggle-group --yes`) and build `ThemeToggle` as a **wrapper** over it — per repo rule F3, do NOT fork `components/ui/toggle-group.tsx`.
- Hydration-safe initial render: the toggle returns a placeholder of identical size until `next-themes`' `useTheme()` reports `mounted`, so server-side HTML and first client render match.
- No new color tokens — the existing `.dark` block already covers everything the dashboard renders. Verification (per CLAUDE.md F4) is to grep the built CSS for `--background`, `--foreground`, etc., and confirm both `:root` and `.dark` variants ship.
- Viewer-mode (share-cookie) sessions get the same toggle. Theme is a pure client preference (localStorage); it never touches `config.yml` or any server state.

## Impact

- **Code**:
  - `apps/web/package.json` — add `next-themes` dependency.
  - `apps/web/components/ui/toggle-group.tsx` (new, generated by shadcn CLI).
  - `apps/web/components/ui/toggle.tsx` (new, generated as a transitive dep of `toggle-group`).
  - `apps/web/components/theme-provider.tsx` (new).
  - `apps/web/components/theme-toggle.tsx` (new — wrapper over `ToggleGroup`).
  - `apps/web/components/theme-toggle.test.tsx` (new — unit test for selection state + a11y labels).
  - `apps/web/app/layout.tsx` — add `suppressHydrationWarning` to `<html>`; wrap `<body>`'s tree in `<ThemeProvider>`.
  - `apps/web/components/app-sidebar.tsx` — refactor the `SidebarHeader` row to a `flex items-center justify-between` layout, with the wordmark `Link` on the left and `<ThemeToggle />` on the right.
  - `apps/web/components/providers.tsx` — wire `ThemeProvider` here if the existing `<Providers>` is the natural composition point (decided during apply; either way one provider mount).
- **CSS**: No changes — `.dark` tokens are already present. Verification only.
- **Tests**: One new component test for `ThemeToggle`. Existing tests remain unaffected (no Provider needed for non-themed components).
- **Build**: `pnpm --filter @memon/web build` cost unchanged (one extra small package + two component files).
- **Risk**: Low. `next-themes` is a single-purpose, widely-deployed library; the toggle is additive UI; no API or on-disk schema changes.
