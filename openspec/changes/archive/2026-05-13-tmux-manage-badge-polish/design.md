## Context

`tmux-manage-split-pane` (archived 2026-05-13) shipped the card-style
list with category + metadata chips. Visual feedback after one day of
use: the row is hard to scan because every chip looks the same. The
user wants a polish pass with icons, prefix labels, and color so each
chip is identifiable at a glance.

This change is purely client-side rendering for `SessionCard` in
`apps/web/app/manage/tmux/tmux-page.client.tsx`. No new dependencies,
no API change.

## Goals / Non-Goals

**Goals:**

- Each chip carries a `lucide-react` icon at its leading edge.
- The three category/agent chips (`Agent`, `Exp`, `Run`) carry an
  explicit prefix label word.
- The ttyd port chip carries a distinguishing emerald border (per the
  user's explicit ask) while keeping the muted background of all
  chips, so it visually reads as "connection live" without yelling.
- The pre-existing standalone uppercase category chip is removed —
  its job is taken over by the target/scope-combined chip.

**Non-Goals:**

- Touch any backend or API.
- Introduce a new icon library or new shadcn primitive.
- Change the order of chips (already ttyd → agent → project → target;
  same order continues).
- Change which rows show which chips (visibility rules stay identical
  to `tmux-manage-split-pane` — only the rendering of each chip changes).

## Decisions

### D1. Icon choices (all from `lucide-react`)

| chip            | icon            | rationale                                           |
|-----------------|-----------------|-----------------------------------------------------|
| ttyd port       | _none_ — emerald dot | per user feedback during apply: a small green dot reads as "live" at a glance and keeps the chip more compact than a `Plug` lucide glyph at `size-3` would |
| Agent           | `Bot`           | generic AI-agent glyph                              |
| Project         | `Folder`        | the project root on disk is conceptually a folder   |
| Run target      | `Zap`           | "run / execution" — quick energetic glyph           |
| Exp target      | `FlaskConical`  | experiment iconography                              |
| Project target  | `FolderTree`    | distinguishes the project-scope link from a generic folder chip |
| Manual          | `Wrench`        | user-built manually                                 |
| Legacy          | `Archive`       | pre-rework leftover                                 |
| Stale           | `AlertTriangle` | unchanged from today                                |

All icons are already in `lucide-react`'s catalog (verified). No
new import beyond `tmux-page.client.tsx`'s existing lucide imports.

Icon size: `size-3` (12px) — matches existing per-chip icon sizing.

### D2. Color treatment per chip

Reusing the same Tailwind color families introduced by
`tmux-manage-split-pane` so the visual language is consistent:

| chip            | bg (light)             | text (light)           | border (light)          | dark adjustments                                 |
|-----------------|------------------------|------------------------|-------------------------|--------------------------------------------------|
| ttyd port       | `bg-muted`             | `text-emerald-700`     | _none_                  | `dark:text-emerald-300`                          |
| Agent           | `bg-orange-100`        | `text-orange-900`      | `border-orange-200`     | `dark:bg-orange-900/40 dark:text-orange-200`     |
| Project         | `bg-muted`             | `text-muted-foreground`| `border-transparent`    | (already adaptive)                               |
| Run target      | `bg-emerald-100`       | `text-emerald-900`     | `border-emerald-200`    | `dark:bg-emerald-900/40 dark:text-emerald-200`   |
| Exp target      | `bg-sky-100`           | `text-sky-900`         | `border-sky-200`        | `dark:bg-sky-900/40 dark:text-sky-200`           |
| Project target  | `bg-violet-100`        | `text-violet-900`      | `border-violet-200`     | `dark:bg-violet-900/40 dark:text-violet-200`     |
| Manual          | `bg-amber-100`         | `text-amber-900`       | `border-amber-200`      | `dark:bg-amber-900/40 dark:text-amber-200`       |
| Legacy          | `bg-muted`             | `text-muted-foreground`| `border-transparent`    | (already adaptive)                               |

(Light values are stand-ins for the existing radix-mira / mist

The Agent color (orange) is a deliberate choice to AVOID conflicts
with run (emerald), exp (sky), project (violet), and manual (amber).
Orange is the unused warm slot that gives the row "claude is the
agent here" a distinct visual identity.

### D3. Prefix label structure

For the three user-listed chips (Agent / Exp / Run), the chip body
becomes `<icon><PREFIX><value>` with a thin space (Tailwind `gap-1`)
between the icon and the prefix, and another between the prefix and
value. Examples (rendered):

```
[🔌] :7683                       — ttyd port
[🤖] Agent claude                — agent
[📁] project-a                   — project (no prefix per the user ask)
[⚡] Run foo-260507-103000       — run target
[🧪] Exp E0042-bar                — exp target
[🌳] Project project-a           — project-scope target
[🔧] Manual                       — manual category
[📦] Legacy                       — legacy category
[⚠] Stale (unknown-target)       — stale
```

(Emoji used as ASCII stand-ins for the lucide icons above; in the real
UI these are SVGs.)

Prefix font weight: `font-medium` (matches the existing category-chip
treatment). Value font: `font-mono`. The mixed weight + family makes
the prefix read as a label and the value as the addressable identifier.

### D4. Standalone category chip is REMOVED from the row

The lead-element category chip introduced by `tmux-manage-split-pane`
(visible as `RUN` / `EXP` / `MANUAL` etc. uppercase) is removed. Its
classification job is taken over by the new combined target/scope
chip — which carries the same color and now an icon and a prefix
label that reads naturally inside the chip row.

This is the alternative to keeping both. The reason for the merge is
that every card today shows BOTH `[RUN]` and `[foo-...]` (target slug)
side by side, where the first is a category label and the second is
the target address. With a `[Zap] Run foo-...` combined chip, the two
collapse into one chip that's still color-coded by category and
remains clickable as a link to the target. Net: fewer chips per row,
no information loss.

### D5. Project chip suppression for scope=project rows

When `parsed.scope === 'project'`, the target chip is itself a
`[FolderTree] Project <project>` chip that already names the project.
Showing a separate `[Folder] <project>` chip would be redundant.
Decision: when scope is `'project'`, omit the standalone project chip.
For all other scopes (`run` / `exp`), the project chip and target chip
are both shown.

### D6. The ttyd-port chip's green dot is the only "live ttyd" affordance

Original request: "green border, background stays the current color".
Refined during apply: replace the icon + border with a small **emerald
dot** glyph (`size-1.5 rounded-full bg-emerald-500`) inside an
otherwise-neutral chip. The dot is compact, signals "live" at a
glance, and removes the chunky border that the original design called
for. The text continues to render in `text-emerald-700` /
`dark:text-emerald-300` to keep the chip's color cue consistent even
without a border. This chip is omitted entirely when `liveEntry === null`,
so "no chip" cleanly communicates "no ttyd here".

### D7. Target chips open in a new tab

Per user feedback during proposal: clicking the Run / Exp / Project
target chip SHALL open the target page in a new browser tab, not in
the current tab. The `/manage/tmux` page itself is a session-management
context the user typically wants to keep around (especially with the
inline terminal pane attached to a session); navigating away in-place
would tear the page down.

Implementation: add `target="_blank"` and `rel="noopener noreferrer"`
to the chip's `<Link>` (Next.js's `Link` accepts these passthrough
attributes — they apply to the underlying anchor element).

`rel="noopener noreferrer"` is the security-recommended pair for any
`target="_blank"` external-style link, preventing the opened page from
accessing `window.opener` and from leaking the referrer header (the
target stays inside the same memon dashboard so referrer leak isn't a
secret risk, but the lint-rule habit is worth keeping consistent).

### D8. Component structure: one `ScopeBadge` for the combined chip

The current `CategoryBadge` + `MetaBadge` pair gets replaced with:

- `MetaBadge({ icon, prefix?, value, color, asLink?, href? })` —
  generic chip with optional prefix label, icon, and link wrapper.
- `ScopeBadge({ row })` — picks the right icon / prefix / color /
  href based on the row's category (run / exp / project / manual /
  legacy / stale) and renders a `MetaBadge`.

`SessionCard` then renders:

```tsx
{row.liveEntry && <PortBadge port={row.liveEntry.port} />}
{p.agent && p.agent !== 'none' && <AgentBadge agent={p.agent} />}
{p.scope !== 'project' && p.project && <ProjectBadge project={p.project} />}
<ScopeBadge row={row} />
```

Where `PortBadge` / `AgentBadge` / `ProjectBadge` are thin wrappers
around `MetaBadge` so each chip type has a single named call site.

### D9. Card visual styling: white background and selected-border ring

Per user feedback during apply:

- The card's default background is **`bg-card`** (i.e. white in light
  mode, the shadcn dark equivalent in dark mode). This replaces the
  previous transparent background that picked up the SidebarInset's
  bg-background and read as "no card".
- The **selected** state replaces the previous left-accent + bg-accent
  treatment with a full **`border-primary`** ring (border color changes
  on all four sides). This gives the selected card a uniform ring
  rather than a one-sided accent bar — cleaner read at a glance, and
  no layout shift (the border width stays 1px).
- Hover state remains `hover:bg-accent/40` for non-stale rows, so the
  pointer-over affordance still reads against the white card surface.

## Risks / Trade-offs

- **[Risk]** Eight different color families on a single row could
  read as "the page is yelling at me". → **Mitigation**: the existing
  card has 5 chips at most simultaneously (port + agent + project +
  target/scope for matchable rows; subset for manual / stale). The
  colors are pastel-saturation in light mode and translucent in dark
  mode, calibrated for the `radix-mira / mist` palette.

- **[Risk]** Lucide icons at `size-3` (12px) lose detail. →
  **Mitigation**: lucide's `Plug`, `Bot`, `Zap`, `FlaskConical`,
  `Folder`, `FolderTree`, `Wrench`, `Archive` all render
  recognizably at 12px (verified against shadcn docs). For very
  high-DPI displays the `size-3` is sharp.

- **[Risk]** Dropping the standalone category chip might confuse users
  who scanned by it. → **Mitigation**: the new target chip carries
  the same color AND an explicit prefix label word — the category
  signal is strictly stronger, not weaker.

- **[Risk]** Eight color classes added inline blow up Tailwind's
  generated CSS size. → **Mitigation**: Tailwind only emits utilities
  for classes actually used. Each color is 6 utility classes (bg /
  text / border / dark-bg / dark-text / dark-border), x 8 chip types
  = 48 utilities. Negligible CSS-bundle increase (<1KB).

## Migration

No data migration. No spec data migration. Source-level rename of
`CategoryBadge` → consolidated under `ScopeBadge` is mechanical.

## Open Questions

- Should the `Folder` icon for scope=project's target chip be
  different from `Folder` for the project-name chip? Currently I have
  `Folder` (file) for project name and `FolderTree` (project tree)
  for project-scope target to avoid ambiguity, but the user can
  request the same icon for both if they prefer.
- Should the prefix label use exact Title Case ("Agent", "Run", "Exp")
  or all-caps ("AGENT", "RUN", "EXP") to mirror the prior category
  chip? Proposal: Title Case, since the prefix reads as a word, not
  a status indicator. Easy to flip if you prefer the old uppercase
  look.
