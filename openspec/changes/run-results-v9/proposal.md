## Why

An Experiment's `results.yaml` mixes three things with different owners: the human-authored comparison design (columns, Variant declarations, plan states, annotations), the machine-produced measurements of every Run, and the Run/attempt bookkeeping. On the largest operator Experiment it is a single 1.36 MB, 30,000-line file with 401 Variants and 117 commits, rebuilt by project scripts that need their own locks and hash CAS; one out-of-vocabulary row makes the whole table unreadable (the live dashboard currently answers `400` for it). Values can only be flat scalars, so statistics are smuggled as strings (616 `mean ± std` strings and 214 JSON strings across 30 Experiments) that sorting, SOTA and CSV export cannot use, and two incompatible per-Run JSON sidecar formats have grown around the gap. FS v9 gives every Run its own tracked result file, keeps the human-authored description of the Experiment's results in one tracked JSON document, and turns the Variant table into a generated, rebuildable cache.

## What Changes

- **BREAKING (FS v9, release 9.0.0).** `FS_CONVENTION_VERSION = 9`. `results.yaml` is retired from the Experiment bundle; a reviewed mechanical migration (`packages/core/migrations/v8-to-v9.md`, commit `chore(memon): migrate FS convention v8 -> v9`) splits it.
- **Per-Run `result.csv` (tracked).** Each Run directory may hold one long-format table with the three columns `path,stat,value`. Dotted paths express groups under the top-level partitions for parameters, metrics and environment values; only `stats` values span several rows (one per `stat`); `list` values are one-line JSON text; `(path, stat)` is unique; `$`-prefixed paths are reserved and the `$experiment_schema_version` row is mandatory. memon writers upsert rows atomically (old values live in Git history). Values describe the whole Run; checkpoints, W&B identities and other source facts belong to the Run record. Per-step results are out of scope.
- **Experiment description file (tracked).** `docs/experiments/E<NNNN>-<slug>/experiment.json` (the file name is defined once in core) holds `experiment_schema_version`, `groups` (display metadata of path groups), `columns` (typed by path: `string`, `number`, `boolean`, `enum` with options, `list`, `stats`; label, unit, direction, `over`/`across` for stats, default display and visibility) and `variants` (id, name, description, plan state including `BLOCKED`, declared parameters and env, provenance, the Variant's `runs`, and frozen historical values without a Run directory). It never repeats README frontmatter (`id`, `slug`, `title`, `status`, `runs` stay in the README); every Variant's `runs` must be a subset of the README `runs`. `implementation.yaml` and `investigation.yaml` are unchanged.
- **Generated summary cache.** `.memon/index/results/<experiment-id>.json` (inside the self-ignored derived index, never tracked, never hand-edited) holds each Variant's effective status, evidence and other Runs, aggregated cells (statistics across a Variant's Runs are generated automatically) and diagnostics, with the fingerprint of every input. Central and the CLI both rebuild it, validated with the v8 fingerprint mechanism.
- **Experiment schema version (hard rule).** `experiment_schema_version` versions one Experiment's result schema (not memon's file format). The description file, every member `result.csv` and the cache record it; a mismatch or missing version fails that Experiment's summary only (`RESULT_SCHEMA_MISMATCH`: CLI non-zero exit, Web error state, both listing every offending file and the upgrade command, never partial data). `memon experiment schema upgrade <exp> --to <N>` applies declarative (or one executable) transforms from `schema-upgrades/`: dry-run first, then backup, atomic rewrite, verification and rollback; it refuses while a member Run is running. A duplicate `(path, stat)` row also fails the summary.
- **Variant status is partly derived.** Humans declare plan and judgment states (`PLANNED`, `BLOCKED`, `DROPPED`, `INCONCLUSIVE`); `RUNNING`, `COMPLETED` and `FAILED` derive from the Variant's Run records. An `INTERRUPTED` Run counts as in progress and is never mapped to `FAILED`. Evidence versus other attempts is derived (finished and not deprecated), so the curated `attempts` list disappears.
- **CLI.** `memon run result get|set|lint`; `memon experiment results table|summary` read the summary (rebuilding it when stale); `memon experiment results rebuild`; `memon experiment schema upgrade`; `experiment create` scaffolds the description file; the annotation helper edits it; lint covers it and the member result files.
- **Web.** The Results table renders the summary: column visibility becomes a vertical tree (partitions, groups, columns; parent checks cascade, partial checks are indeterminate) replacing the horizontal checkbox strip, and ordering is done by dragging tree nodes vertically — whole groups as blocks, members within their group, never across groups — so displayed columns of one group stay contiguous (header drag is an optional secondary entry); stats cells render by a display path or pattern (`max.p99`, mean ± std, mean (min–max)), sort and SOTA use a selected statistic and the column direction; a blocking error card replaces the table on schema mismatch or duplicate rows; Views address columns by path with a read-time alias for legacy flat keys.
- **Derived index `index_version: 2`.** Run entries gain the `result.csv` fingerprint and recorded schema version; Experiment bundle fingerprints cover the description file; the index directory gains `results/`.
- **Skills.** Writers declare columns and Variants in the description file, record measurements through `memon run result set` (or direct edits that keep the rules), never edit the cache, and use the schema upgrade command; higher-level skills keep reading Variant-level results only, now through the summary.
- **Provisional.** The exact syntax — CSV header and reserved-row placement, path grammar and partition names, the two-level stats spelling, field names of the description file, aggregation details, display patterns and the defaults of the column tree — is being settled with the user and is marked provisional in `design.md`; the specs fix behavior, not those spellings. Confirmed details will be folded in through `opsx:update`.

## Capabilities

### New Capabilities
- `run-results`: the per-Run `result.csv` contract — location and tracking, reserved rows, path grouping and partitions, value types including `stats` and `list`, uniqueness, upsert writers and lint.
- `experiment-results-summary`: the generated per-Experiment summary cache — inputs and fingerprints, effective Variant status, evidence derivation, aggregation across Runs, the schema-version and duplicate gates, rebuild and error reporting.
- `experiment-schema-upgrade`: per-Experiment result-schema versioning and the one-command upgrade with dry run, backup, atomic rewrite, verification and rollback.

### Modified Capabilities
- `structured-experiment-sections`: the bundle's Results source becomes the description file; Variant declarations, Variant `runs`, plan states, groups, typed columns, enum options, annotations and env values move into it; Results projections come from the summary.
- `derived-index`: `index_version: 2`, the `results/` cache directory, Run result fingerprints and the description-file bundle fingerprint.
- `memon-cli`: results table/summary/annotation on v9 sources, Run result commands, results rebuild, schema upgrade, Experiment document commands.
- `experiment-results-views`: column identity by path, tree visibility and group order, stats display and sort selections, legacy flat-key alias.
- `web-dashboard`: Results card and table on the summary, column tree and group dragging, stats rendering, blocking error state, refresh inputs.
- `cluster-backend-api`: the Results snapshot route serves the summary and reports schema mismatches.
- `experiment-edit`: `create` scaffolds the description file; `--from-run` seeds a Variant whose `runs` list the Run and maps no status; `delete` removes the new bundle files and the summary.
- `run-edit`: Run rename rewrites the Run path in the README `runs` and in Variant `runs`.
- `wiki-store`: Variant sources resolve through the description file.
- `experiment-discovery`: the slim list reads no description or result file.
- `live-updates`: refresh coverage names the v9 Results inputs and the single summary cache.
- `lightweight-execution-workflow`: higher-level skills read Variant-level results from the summary, never per-Run result files.
- `memon-skills`: authoring rules for the description file and `result.csv`, cache prohibition, schema upgrades, v8→v9 migration.
- `fs-version-tracking`: the convention value becomes 9 (release 9.0.0).
- `fs-migration-runtime`: the reviewed v8→v9 migration and its guide/version gate.

## Impact

- **Filesystem (MAJOR):** new `experiment.json` per bundle, per-Run `result.csv`, optional `schema-upgrades/`, cache under `.memon/index/results/`; `results.yaml` removed by the migration; marker 9. Release 9.0.0 with `MEMON_CHANGED_SURFACES=central,cli,skills,filesystem`.
- **Core:** result file parser/serializer/upserter, description-file schema and lint, summary generator and fingerprinted cache, schema-upgrade engine, derived-index v2, v8→v9 planner/apply/verify, guide.
- **CLI:** new `run result`, `experiment results rebuild`, `experiment schema upgrade`; changed results/annotation/doc/create/delete/rename commands.
- **Backend / Web (central):** Results snapshot from the summary, background regeneration, Results table tree controls, group ordering, stats rendering and error card, Views path ids and alias.
- **Skills:** `memon-write-experiment-doc`, `memon-run-experiment`, `memon-write-script`, `memon-read-results`, `memon-propose`, `memon-drive`, `memon-migrate-fs` and the shared bundle reference.
- **Operator projects:** a reviewed migration per project; projects whose `.gitignore` excludes Run directories must allow `result.csv` (the plan reports it as a blocker); per-Run JSON sidecars of the two legacy shapes are converted and left in place for the operator to delete.
- **Ordering:** applies after the active change `results-accept-blocked-variants` is archived (its `BLOCKED` status and env-string requirements are the base of several MODIFIED blocks here). `run-record-and-resume` and `run-scheduler` depend on this change.
- **Rollback:** revert the migration commit (marker back to 8, `results.yaml` restored from Git); deleting `.memon/index/` is always safe.
