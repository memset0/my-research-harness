# FS convention v10 to v11

## Background / Why

V11 makes new experiments lightweight: a human-readable README, small presentation
settings, explicit Run execution records, and a saved result table. It removes
mandatory phase documents and research epochs for newly converted experiments
(change: `lightweight-research-integration`).
Redoing an invalidated research basis creates a new Experiment ID. Retirement
and measurement invalidity remain separate.

This is a scoped, semantic migration. Convert only the Experiments the user
selected. Keep all others in legacy form; V11 reads both. Do not convert a
project during deployment. Preserve native outputs and extract only useful
metrics; an empty result CSV does not mean an execution produced no evidence.

## Detection

Set `MEMON_SOURCE` to the installed memon checkout; build its CLI dependency
closure if needed. Scripts use its matching built core library.

- Read the marker with `jq . .memon/version.json`; inspect declarations even when the marker is already 11.
- Check a selected declaration with `jq -r '.format // "legacy"' docs/experiments/E0001-example/experiment.json`.
- Produce a plan without modifying sources: `node "$MEMON_SOURCE/packages/core/migrations/scripts/v10-to-v11.mjs" --project-root . --experiment E0001-example > /tmp/experiment-migration-plan.json`.
- Inspect its actual moves, selected Runs and qualifications with `jq '{experiment,runs,description,remove}' /tmp/experiment-migration-plan.json`.

## Diff (v10 → v11)

1. Read the generated plan. Correct draft descriptions, smoke assignments,
   exclusions and current conclusions using the original evidence. Never infer
   a measurement's validity from the Experiment's lifecycle.
2. Review each selected Run. Retain original creation/start/finish times with
   offsets. Missing creation times require an explicit correction; never use
   filesystem timestamps. Reject running or queued work. Resolve shared Run
   ownership and multiple research generations before conversion.
3. Set `remove` only for obsolete `implementation.yaml` and
   `investigation.yaml` whose useful findings are already preserved. Rewrite
   the planned README; remove obsolete pointers, execution recipes and empty
   template sections. Keep conclusions, caveats and useful evidence links.
4. Add `logs/E????/V????/*` and `logs/E????/smoke/*` to the existing `run_dirs`
   in `.memon/project.yml`; preserve other patterns and custom fields. Check
   central layout overrides by reading the selected instance configuration when
   applicable. Do not change unrelated deployments.
5. Apply the scoped plan: `node "$MEMON_SOURCE/packages/core/migrations/scripts/v10-to-v11.mjs"
   --project-root . --experiment E0001-example --apply /tmp/experiment-migration-plan.json`. The command checks source
   hashes, saves preimages under ignored `.memon/migrations/`, moves directories,
   writes metadata, leaves relative old-path symlinks, and rebuilds the inventory.
   It does not change the FS marker. Stop on any error; inspect the backup and
   verify source state before retrying.
6. Extract only the metrics needed for current comparisons, then run
   `memon --project-root . refresh E0001-example`. Do not
   synthesize missing values. Commit the saved table and small metadata, not
   large native outputs or the index. Preserve existing artifact retention.
7. Run Verification. After the selected scope passes and the project snapshot
   is complete, set `.memon/version.json` to `fs_convention_version: 11`, retain
   `installed_at`, and set `last_migrated_at` with `date +%Y-%m-%dT%H:%M:%S%:z`.
   This selects writer-published inventory mode; it does not claim every legacy
   Experiment was converted. Rebuild the index once after direct edits.

### Experiment README

```before
---
id: E0001-example
status: ACTIVE
runs: [logs/trial-260901-120000]
---
## Implementation
> Managed in [implementation.yaml](./implementation.yaml); read and update that file directly.
```

```after
---
id: E0001-example
status: ACTIVE
---
# Research question
Explain the current comparison and its limitations. Link supporting artifacts.
```

Preserve custom frontmatter verbatim. The planner removes only the managed
`runs` list; edit the planned body deliberately, not through a universal outline.

### experiment.json

```before
{"experiment_schema_version":1,"research":{"current_version":1,"versions":[],"run_versions":{}},"variants":{"V0001":{"name":"Baseline","runs":["logs/trial-260901-120000"]}}}
```

```after
{"format":"lightweight","columns":[]}
```

Store optional names, partial parameters, independent `active` flags and assessment
reasons in run.json. Directory ownership replaces binding lists. Prepare a READY
Run for an unexecuted Variant; its creation time is the migration-time record
creation, not an invented historical execution time. Preserve deprecated Variant
identities and reasons only when useful. Configure custom aggregation under
`variants.V0001.aggregate`; otherwise multiple active inputs fail closed.

### Run records and paths

```before
logs/trial-260901-120000/README.md
---
id: trial-260901-120000
status: FINISHED
created_at: 2026-09-01T12:00:00+08:00
---
```

```after
logs/E0001/V0001/trial-260901-120000/run.json
{"id":"trial-260901-120000","status":"FINISHED","active":true,"created_at":"2026-09-01T12:00:00+08:00"}
```

Move native files unchanged. Use `smoke` as the directory for checks and exclude
it from formal aggregation. Keep old directory aliases for artifact references;
Preserve useful old headings and bodies under optional `legacy_sections` in
run.json; these fields are deprecated format, not invalid measurements. Remove
reviewed obsolete execution recipes rather than maintaining them. Update direct links to removed README
files to the Run view or an appropriate retained explanation before publishing.
Do not mistake an alias for an additional Run during discovery.

### Run result.csv and Experiment results.csv

```before
path,stat,value
$experiment_schema_version,,1
metrics.loss,,0.2
```

```after
path,stat,value
metrics.loss,,0.2
```

The tracked Experiment table is new:

```after
variant,path,stat,value
V0001,metrics.loss,,0.2
```

There are no generated-at, schema or cache fields in this table. Explicitly
selected `run.*` columns can contain execution metadata from `run.json`.

### Optional phase documents

```before
implementation.yaml
investigation.yaml
```

Delete only the reviewed obsolete files listed in the plan. Preserve useful
independent technical material in `details/`; preserve main evidence and
conclusions in the Experiment README. Existing optional documents remain readable.

### .memon/project.yml, .memon/index/ and .memon/version.json

```before
schema_version: 1
run_dirs: [logs/*]
```

```after
schema_version: 1
run_dirs: [logs/*, logs/E????/V????/*, logs/E????/smoke/*]
```

Rebuild the ignored index; never hand-edit or commit it. Missing or invalid
FS11 snapshots produce an explicit repair error, not a background directory walk.

If the project ignores logs, retain that policy for native outputs while allowing
the new small records and tables to be tracked. For example, after `/logs/**`:

```gitignore
!/logs/
!/logs/**/
!/logs/E????/*/*/run.json
!/logs/E????/*/*/result.csv
```

Verify these paths with `git check-ignore`; do not force-add whole output directories.

```before
{"fs_convention_version":10,"installed_at":"2026-09-01T12:00:00+08:00","last_migrated_at":null}
```

```after
{"fs_convention_version":11,"installed_at":"2026-09-01T12:00:00+08:00","last_migrated_at":"2026-10-20T12:00:00+08:00"}
```

Use the actual local migration timestamp, not the example.

## Target State (v11 Summary)

Selected experiments have README + lightweight experiment.json + saved
results.csv. Runs live in `logs/E<NNNN>/<V<NNNN>|smoke>/<runid>/`, contain
`run.json` and native artifacts, and need no README. Run records carry partial
parameters, optional names, active flags and assessment reasons; directory paths
provide Experiment and Variant ownership. Old path aliases resolve retained
artifacts. Legacy experiments outside the selected scope remain byte-identical.
The source-side CLI publishes a complete rebuildable inventory for read-only
websites. No research epoch, mandatory phase tracking or Wiki review ledger is
needed. Static HTML and ordinary Wiki content remain readable.

## Verification

1. Check the converted declaration and Run metadata against their CLI parsers.

```sh
set -eu
memon --project-root . show E0001-example | jq -e '(.parseErrors // []) | length == 0'
memon --project-root . show logs/E0001/V0001/trial-260901-120000 | jq -e '(.parseErrors // []) | length == 0'
jq -e '.format == "lightweight" and (has("research") | not)' docs/experiments/E0001-example/experiment.json
printf 'OK: lightweight documents\n'
```

2. Validate and publish the saved results and inventory. Use the actual selected
   Experiment and Run paths in place of the example.

```sh
set -eu
memon --project-root . refresh E0001-example
memon --project-root . refresh
memon --project-root . show
head -n 1 docs/experiments/E0001-example/results.csv | grep -x 'variant,path,stat,value'
test -f logs/trial-260901-120000/run.json
printf 'OK: results, registry and historical alias\n'
```

3. Check tracked scope and content. Inspect explicit source/output checksums
   recorded during the migration; verify unchanged native artifacts and all
   retained historical links. Reject unrelated changed files.

```sh
set -eu
git diff --check
git status --short
git diff --stat
printf 'OK: review the listed scope before committing\n'
```

## Rollback Notes

Use the exact migration commit message `chore(memon): migrate FS convention v10 -> v11`.
If a committed migration must be reversed, run `git revert <migration-commit>`
and restore ignored native output directories from the external backup with
`tar -xpf <backup.tar> -C <project-root>` after checking current running work.
For an interrupted uncommitted application, report the error and saved
`.memon/migrations/` preimages; the helper rolls back its own directory moves
and source writes on a failed step. Do not reset unrelated changes. Rebuild the
index after recovery. A Git-only rollback does not restore untracked artifacts.

## Edge Cases

- Missing required README, declaration or Run metadata: abort and repair from
  actual evidence. Missing result.csv is valid; do not manufacture measurements.
- Custom frontmatter: preserve all custom fields and their source spelling;
  only remove managed membership. Unknown Run fields stay in run.json unless
  explicitly identified as obsolete. Preserve semantic qualifications in notes.
- Dirty working tree: follow the migration runtime's clean-tree requirement.
  Explicit scoped dirty-tree authorization permits only fingerprinted owned
  files with backups; never stash, discard or include unrelated edits.
- Concurrent migration: coordinate one operator per project. The helper takes
  a writer lock and verifies hashes, but external/manual writes do not honor
  that lock. A conflict invalidates the old plan; read and plan again.
- Running/queued Runs: leave their experiment in legacy format until they stop.
  Never relocate an executing directory to satisfy a layout convention.
- Old research generations or shared membership: do not flatten them into
  current evidence. Resolve the scientific boundary with the owner first.
- Untracked large outputs: back them up separately, record checksums and keep
  existing retention policies. The helper moves files locally; it does not make
  untracked outputs appear on another Git clone.
- CLI failure after source writes: report partial completion and the named
  repair command. Do not repeat creation blindly or claim the cache is current.
