# FS convention v11 to v12

## Background / Why

V12 introduces discussion bundles and their published catalog (change:
`add-discussions`). This is an explicitly reviewed additive convention boundary.
Preserve every existing Experiment, Run, Wiki and Report document. Do not
convert previous Report-based discussions automatically. Perform this migration
only after the owner explicitly selects the Project for migration.

## Detection

- Run `jq -e '.fs_convention_version == 11' .memon/version.json`.
- Run `test -f .memon/project.yml && echo 'OK: Project declaration exists'`; abort and repair registration deliberately if it is absent.
- In Git mode, run `test -z "$(git status --porcelain)" && echo 'OK: working tree clean'`; abort on any pre-existing edit.
- In non-Git mode, run `tar -czf ../project-a-before-v12.tar.gz .memon/version.json && test -s ../project-a-before-v12.tar.gz && echo 'OK: backup created'`.

## Diff (v11 → v12)

### `.memon/version.json`

```before
{
  "fs_convention_version": 11,
  "installed_at": "2026-11-01T10:00:00+08:00",
  "last_migrated_at": null
}
```

```after
{
  "fs_convention_version": 12,
  "installed_at": "2026-11-01T10:00:00+08:00",
  "last_migrated_at": "2026-11-08T10:00:00+08:00"
}
```

1. Run `memon --project-root . refresh`. Abort if it fails. It publishes the
   ignored discussion catalog, including an empty catalog when no discussions
   exist. Read every reported question diagnostic and preserve its source.
2. Run `jq -e '.catalog_version == 1 and .kind == "discussions"' .memon/index/discussions.json`.
3. Save the current marker with `cp .memon/version.json .memon/version-v11.backup`.
4. Set `MEMON_MIGRATION_STAMP=$(date '+%Y-%m-%dT%H:%M:%S%:z')`.
5. Run `jq --arg at "$MEMON_MIGRATION_STAMP" '.fs_convention_version = 12 | .last_migrated_at = $at' .memon/version.json > .memon/.version-v12.tmp`.
6. Run `cmp -s .memon/version.json .memon/version-v11.backup`; abort if the marker changed concurrently.
7. Run `mv .memon/.version-v12.tmp .memon/version.json`. Preserve installed_at and all unknown marker fields.
8. Run Verification. In Git mode stage only `.memon/version.json` and use the exact commit subject in Rollback Notes. Remove the temporary backup after successful verification.

### `.memon/index/discussions.json` (ignored, disposable)

```after
{
  "catalog_version": 1,
  "kind": "discussions",
  "generated_at": "2026-11-08T10:00:00+08:00",
  "entries": []
}
```

The example is an empty Project; retain actual entries when discussions exist.
No research document, response log or tracked declaration changes.

## Target State (v12 Summary)

The marker records 12. Existing research documents retain their bytes. The
ignored `.memon/index/` contains experiments.json, wiki.json, reports.json and
discussions.json. Optional discussions use
`docs/discussions/D<NNNN>-<slug>/README.md` with DRAFT, OPEN or CLOSED status,
one append-only responses.jsonl and relative assets. No discussion is required.

## Verification

Run these numbered steps in order; stop on every non-zero exit.

1. Verify the marker and catalogs:

```sh
jq -e '.fs_convention_version == 12 and (.installed_at | type == "string") and (.last_migrated_at | test("[+-][0-9]{2}:[0-9]{2}$"))' .memon/version.json && echo 'OK: v12 marker'
jq -e '.kind == "discussions" and .catalog_version == 1 and (.entries | type == "array")' .memon/index/discussions.json && echo 'OK: discussion catalog'
memon --project-root . refresh --check && echo 'OK: published catalogs current'
```

2. In Git mode, verify research files and ignored inventory:

```sh
git diff --exit-code -- docs logs .memon/project.yml && echo 'OK: research documents unchanged'
git check-ignore .memon/index/discussions.json && echo 'OK: disposable catalog ignored'
```

## Rollback Notes

In Git mode commit exactly `.memon/version.json` using
`chore(memon): migrate FS convention v11 -> v12`. If verification fails before
commit, restore the saved marker after checking that it still contains this
migration's postimage; report the failure and leave research documents intact.
After commit, use `git revert <migration-commit-sha>`. In non-Git mode restore
the backup with `tar -xzf ../project-a-before-v12.tar.gz -C .` after checking
for concurrent edits. Ignored catalogs can be discarded and rebuilt; preserve
any newly authored discussion bundles and responses when rolling back tooling.

## Edge Cases

- Missing required marker or declaration: abort. Do not infer FS11 or initialize an existing unmarked research Project during migration.
- Missing optional discussions directory: publish an empty discussion catalog; create no artificial discussion.
- Custom frontmatter and marker fields: preserve them. Change only the two owned marker values; do not rewrite research frontmatter.
- Dirty working tree: follow the migration runtime's default refusal. Obtain separate scoped authorization before handling user edits; never stage them automatically.
- Concurrent migration: the operator must prevent overlapping invocations. The marker comparison detects one conflict; it does not provide a distributed migration lock.
- Invalid questions or response history: keep the original bytes and surface source-line diagnostics. Do not delete or silently repair them to pass verification.
- Older File Agent: install and grant scoped-append-v1 independently before enabling website responses. This Project migration does not upgrade services or widen grants.
