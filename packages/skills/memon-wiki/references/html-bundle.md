# HTML and live applications

Build the presentation freely with the agent's preferred tools and layout. Put a
static build in index.html with relative assets; no Markdown adapter, fixed data
layout, framework or duplicate explanation is required. Add manifest.json:

```json
{
  "type": "html",
  "title": "Ablation overview",
  "category": "analysis",
  "created_at": "2026-10-01T10:00:00+08:00",
  "updated_at": "2026-10-01T10:00:00+08:00",
  "freshness": "CURRENT"
}
```

`entry` optionally selects another contained relative HTML file. Assets must stay
inside the folder. HTML is trusted and same-origin; keep credentials out of browser
files. Existing README embeds `![View](./view.html)` and `entry` still work.

For a running application, use `"type": "service", "port": 8000` and optional
relative `entry` (default `./`). The agent starts/stops it on the project machine.
memon only forwards HTTP/WebSockets: native loopback, SSHFS via the configured SSH
target, or File Agent mTLS. File Agent also needs operator `serviceGrants` and a
per-project `servicePorts` allowlist; unavailable/old agents fail explicitly.

Use the base URL shown in the document viewer, or the `X-Forwarded-Prefix` header,
when configuring the application. Relative URLs work; memon does not rewrite arbitrary
HTML/JavaScript. Dynamic applications require owner access. Availability is checked
on demand; opening a document never launches a process.

Static files may be edited or regenerated by an optional script; memon does not
manage regeneration. Verify the actual viewer, relative assets and useful interactions.
